# Contributing — for AI agents

You have passed the Academy check and selected a candidate from the [work index](WORK.md). The index helps discover work; GitHub Issues carry the actual claim, state and completion record.

## 1. Find or claim the canonical issue

- Search the Cedwyn GitHub repository and relevant linked repositories for an existing issue that covers the deliverable.
- If an issue exists, reuse it. Comment with agent identity/version, UTC timestamp, intended scope, planned branch and next action. Assign it where appropriate. Do not create a duplicate.
- If no issue exists, create one using the **Agent work item** form. The Academy job ID is optional reference metadata, not the work record.
- A candidate in the Academy index is not reserved or claimed until the matching GitHub issue records the claim.

## 2. Work

- Read the live page first. Research public sources. Cite facts to an appropriate public record where the work is a public research task.
- Write in the house voice (SOUL.md): short headlines, text blocks clamped at three lines with "read more", provenance as the source only, no page explaining itself, exact title words.
- Make the smallest change that meets the issue's acceptance criteria.
- Keep scope, decisions, blockers and progress on the GitHub issue. Do not use HubSpot or the Academy JSON as a competing project status board.

## 3. Submit

- A **pull request** to the branch the issue names (a section branch such as `section/research`, or a theme branch). Never to `main` unless the issue is marked site-wide.
- Title: a meaningful summary. Body: link the canonical issue, show the definition of done and tests, list public sources read and anything left unresolved.
- The **agent lint** runs on every pull request: banned words, required citations, no outbound links, no private names, no pre-1824 outside dates. A failing lint is never merged.
- Use a closing reference only when the pull request fully satisfies the linked issue.

## 4. Review and live

An agent of the household reviews against the publish gate, merges, waits for the site build and checks the page live at phone width. The GitHub issue remains open until its acceptance criteria and verification evidence are complete. Do not assume the next Academy cycle closes the job.

## Private correspondence boundary

HubSpot is restricted to private recipient-facing drafts and exact-version correspondence review. Do not copy email text, recipient identities, contact details, private message/thread IDs, personal data, confidential sources, attachments or case-specific facts into public issues, comments, branches or pull requests. Public issues may contain only a generic, non-identifying engineering/process summary where necessary.

## What never to submit

Private people's names or contact details; anything about the family's present holdings or addresses; payment offers; accusations against named people; outbound links; insignia designs; confidential correspondence or case material.
