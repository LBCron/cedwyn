Ticket Tailor waitlist settings for the walk: pre-sale capture, sold-out capture, broadcast release

Date: 4 Nov 2026 (harvest). Topic: the exact Ticket Tailor switches for capturing demand before a date is confirmed and after it sells out. Builds on ticket-tailor-vs-eventbrite-walk-ticketing-uk.md (fees/choice), pilot-walk-presale-minimum-numbers-hold-then-charge.md (minimum numbers) and coming-soon-notify-me-waitlist-referral.md (generic waitlist). This file is the platform how-to only.

What the primary sources state (Ticket Tailor Help Centre / blog, read 4 Nov 2026)

  • Waitlist (help article written 18 Jun 2026): Events -> event -> Edit event and ticket types -> Advanced settings -> tick Activate waitlist. Option Show only when no tickets are available. Form text is editable. Buyers enter an email on the event page or widget; the event description shows on waitlist-only checkout pages. Multi-date calendars label each date "Waitlist" or with availability.
  • Release: event -> Waitlist sign-ups (pick the date for recurring events) -> Create Broadcast -> email with the buying link. Notified people move from "New signups" to "Notified signups"; sign-ups can be downloaded.
  • Before sale (help article written 20 May 2026): activate waitlist, then set each ticket type to Hidden or Hide until a set date and time; publish the event (a Draft event shows no waitlist form). This turns the event page into a "register interest" page with no extra tool.
  • Blog (9 Oct 2026, vendor): 73,000+ event creators; recurring events/time slots share details and ticket types; duplicate event; buyer self-serve resend/reschedule/cancel; Broadcasts to ticket buyers.
  • No conversion rate for waitlist -> purchase is published by Ticket Tailor; we found no practitioner number. Treat any figure as unknown until our own log has one.

How to do it

  1. Create the walk as a recurring event with candidate dates as occurrences (one setup, per-date capacity).
  2. Before a date is confirmed: waitlist on, ticket types Hidden. Publish. The page now collects emails per date, which is demand evidence for the minimum-numbers decision.
  3. Decide go/no-go per date from sign-ups (minimum-numbers rule in the pilot-walk skill). Unhide tickets for go-dates; broadcast those sign-ups first with a 48 h head start before announcing publicly.
  4. After sell-out: keep waitlist on with "Show only when no tickets are available"; on any cancellation, broadcast to New signups for that date.
  5. Download sign-ups after each walk; they are consented to waitlist contact for that event only, so do not add them to the newsletter without a separate opt-in.
  6. Track: sign-ups per date, tickets bought within 7 days of a broadcast, cancellations refilled. Compare against the walk page's own UTM visits.

Counter-read

  • An email typed into a waitlist is a weak signal; expect many not to buy. Use it to rank dates, not to forecast revenue.
  • Broadcasts are Ticket Tailor emails: deliverability and sender reputation are theirs, not ours; check one test broadcast lands in a Gmail inbox before relying on it.

How we apply it to Cedwyn

  • Use this only if the project lead approves Ticket Tailor and a walk price/dates (PROPOSED in the ticketing skill). Opening the account and any setting change are his decisions; nothing done here.
  • When approved: one recurring "Llandough heritage walk (pilot)" event, 3 candidate Saturdays, tickets hidden, waitlist on, linked from the walk page with ?utm_source=site&utm_campaign=walk_waitlist. Free talks can use the same pattern at £0 (no Ticket Tailor fee on free tickets up to its yearly allowance per the ticketing skill).
  • Public text: never name the project lead; banned words; no addresses; meeting point only as the site already shows it.
